# EDA 结论整理

## 这份文档的定位

这份文档只保留对建模、验证和特征设计真正有用的 EDA 结论，不再记录任务号、日志路径、本地证据、提交流程或确认痕迹。

## 核心结论

1. 验证切分必须尊重真实时间，不能把文件顺序或 row group 顺序当成时间顺序。
2. 线上 Eval 窗口与公开训练集时间轴无缝相接，因此时间特征、验证方案和训练窗选择都必须围绕时间尾部来设计。
3. `62~66` 和 `89~91` 不是同一类用户特征，不能继续混着做 pair。
4. `83~85` 更像一组层级链或语义簇，不适合当作三列彼此独立的普通离散特征。
5. 长序列问题是真问题，尤其 `seq_c` 和 `seq_d`，后续建模必须正面处理。
6. baseline 的高基数重初始化默认策略过猛，把阈值抬到 `30000` 左右更合理。
7. `0`、missing、padding 语义混杂是底层问题，优先级不低于继续堆小特征。

## 数据与时间结论

### 公开训练集整体特征

- 公开训练集总量是 `1010000`，整体正样本率约为 `0.0959`。
- 时间跨度是 `2026-03-18 17:00:28` 到 `2026-03-23 07:40:35`，这里按 `UTC+8` 理解。
- 文件顺序不能代表时间顺序。相邻文件最大时间单调比例只有 `0.5135`，完全前后不重叠的比例是 `0`。
- row group 同样没有稳定时间顺序，因此不能用 row group 尾部替代真实时间尾部。

### 线上测试窗口

- 线上 Eval 样本数是 `310000`。
- 时间窗口是 `2026-03-23 07:40:35` 到 `2026-03-23 09:13:44`，按 `UTC+8` 看主要落在周一早晨 `7` 到 `9` 点。
- 测试集最小时间戳正好等于公开训练集最大时间戳，说明线上测试与公开训练集在时间轴上是直接接续的。
- 这解释了为什么 weekend 和 night 这类粗时间标记不一定稳定提分，也说明最近时间窗口验证比随机切分更可信。

### 验证切分与训练窗

- `93` 分钟尾窗和 `98` 分钟尾窗非常接近，已有 `93` 分钟设定就可以继续沿用，没有必要切回 `98` 分钟。
- `93` 分钟尾窗下，训练正样本率约为 `0.0892`，验证正样本率约为 `0.1143`，尾部明显更偏正样本。
- 最近窗裁切不是样本量不够的问题，而是新旧分布权衡的问题。
- `24h` 到 `48h` 是最值得优先尝试的训练窗区间。这个区间仍然保留了大部分训练样本，但分布更贴近最后 `93` 分钟。
- `72h` 以后旧分布会明显回流，继续加更早数据的收益会变弱，反而更容易稀释尾部模式。

## ID、序列与结构性结论

### ID 侧

- `user_id` 基本没有复用空间，公开训练集里是全量唯一，因此 UID Embedding 没有学习价值。
- `item_id` 有明显重复，仍然具备聚合价值，Item 侧建模值得保留。

### 序列侧

- 四条历史序列都没有未来时间泄漏，且时间顺序基本稳定，整体上是从近到远排列。
- 长序列问题真实存在：
  - `seq_d` 的长度分布约为 `p50=2715`、`p90=3870`、`p99=3961`
  - `seq_c` 的长度分布约为 `p50=370`、`p90=1055`、`p99=2551`
- `domain_c_seq_47` 与 `item_id` 没有 exact match，全量上 `any_match_rows=0`，因此这条路不值得继续作为主收益点。

### 用户 Pair 与层级特征

#### `62~66`

- `62~66` 适合继续做 pair，而且是当前最明确的用户侧主方向。
- 这组特征的模板复杂度很高，不是几种固定离散模板，说明它们确实承载了结构信息。
- missing 本身就是信号，而且 missing 的正样本率 consistently 高于 non-missing。
- 结论是这组特征不能被简单并入普通 dense 分支，应该保留 pair 建模，并显式建模 missing state。

#### `89~91`

- `89~91` 不适合继续做 pair。
- 它们的离散模板复杂度几乎没有，结构上不像复杂 pair，更像数值型或状态型用户特征。
- 这组特征更适合单独走 dense 或数值分支，而不是继续在 pair 方向投入。

#### `83~85`

- `83~85` 不是三列彼此独立的普通离散特征，更像层级链或语义簇。
- presence 本身就是强信号，但数值桶关系不是简单单调关系，因此不适合粗暴按 scalar 大小处理。
- 这组特征适合按层级或分组语义来建模，而不是独立 one-hot 式处理。

### 底层语义冲突

- 多个 int 特征里，`0`、missing、padding、全零行在当前表示里容易混在一起。
- 这会同时污染离散语义、缺失语义和序列语义，是比继续加零碎特征更底层的问题。
- 后续如果不先拆清这些语义，很多上层结构都会被噪声抵消。

## 时间相关结论

### 样本相对时间本身是强信号

- 越靠近时间尾部，正样本率越高。
- 这不仅体现在验证切分上，也体现在时间相关数值和近期窗口统计上。
- 时间不是普通辅助特征，而是决定分布、验证口径和序列有效性的主导条件。

### 时间对不同序列的作用并不一样

- 在最后 `93` 分钟尾窗里，freshest history 的主导域是 `seq_d`，覆盖最广。
- 但 burst 模式下，最有价值的主导域反而更偏向 `seq_c`。
- 这说明时间条件不只是告诉模型 哪些 token 更近，而是在告诉模型 当前该更信哪条序列、该按哪种行为模式选历史。

### 不同序列的时间收益不同

- `seq_c` 的短窗命中覆盖虽然不大，但一旦命中，正向 lift 很强，更像高价值短时激活。
- `seq_d` 更像覆盖最广的 freshness 主通道，但它在极近时间窗下不一定自动带来正向 lift。
- 因此后续时间建模不能只做统一时间 bias，而应允许不同域在不同时间规则下拿到不同权重。

## 重初始化与嵌入谱结论

### 重初始化阈值

- `threshold > 100` 会误伤过多 embedding 表。
- `threshold > 1000` 已经比 `100` 明显稳，但仍然会打到一些不该优先重置的表。
- `threshold > 30000` 更接近合理阈值，留下来的才主要是那些真正高风险、超高基数、又很稀疏的序列表。

### 真正高风险的表

- 高风险重置对象主要集中在少数超高基数序列表，例如 `seq_a:38`、`seq_d:22`、`seq_d:23`、`seq_b:74`、`seq_b:76`、`seq_b:88`、`seq_c:36`。
- 一些在 `100` 阈值下会被重置的表，其实不该被误伤，因此不建议把阈值退回太低。

### 嵌入谱诊断

- 真正出现明显主方向塌缩的，主要还是部分序列表，例如 `seq_a_fid_45`、`seq_d_fid_22`、`seq_d_fid_23`。
- `62~66` 这组 aligned user pair 虽然高基数，但谱形态并不属于最该优先重置的那一类。
- 像 `abs_night`、`abs_weekend` 这种天然取值很少的小表，低秩并不代表训练坏掉，不能误判。

## 匹配、交叉与条件特征结论

### Item 与序列匹配

- 高覆盖不等于高区分度。比如某些 `item` 与 `seq_d` 的 any match 覆盖几乎打满，但正样本率几乎贴着基线，不能当强特征。
- 更有意义的是那些覆盖适中、但存在稳定正向 lift 的匹配关系，尤其围绕 `83~85` 一类层级特征时更明显。
- `item13_seq_a41`、`item6_seq_d24` 这类关系更像真实行为证据，值得保留到后续 attention 或 gate 机制里。

### Item 内部交叉与 Item 和用户交叉

- Item 内部交叉、Item 与用户状态交叉、Item 与用户 dense 条件交叉，原始 lift 确实很强。
- 但这些强信号大多覆盖很小，更像热点簇或细分语义簇，而不是适合全量枚举接入的宽特征。
- 因此它们更适合少数白名单、可学习门控、小规模 evidence token，而不适合直接一股脑拼进大 MLP。

### `item11` 的定位

- `item11` 有信息，但更像 count bucket 和少数 value 白名单的问题，不像一个值得优先做序列 overlap 的方向。
- 它的 value 级热点可能很强，但覆盖偏小，更接近值记忆而不是稳定行为关系。

## 直接指导建模的建议

1. 验证切分继续采用真实时间尾窗，优先沿用 `93` 分钟方案。
2. 训练集最近窗优先尝试 `24h` 到 `48h`，而不是直接吃全时段旧分布。
3. `62~66` 保留 pair 建模，并显式建模 missing state。
4. `89~91` 改走 dense 或数值分支，不再继续按 pair 主方向处理。
5. `83~85` 按层级链或语义簇建模，不要拆成彼此独立的普通离散列。
6. 先解决 `0`、missing、padding 的语义冲突，再谈继续堆更多零碎特征。
7. 高基数重初始化阈值优先按 `30000` 一档考虑，不建议退回 `100`。
8. 时间条件应直接进入 attention 打分，而不只是停留在 token 表示层。
9. 不同序列应允许不同时间规则和不同权重，尤其区分 `seq_d` 的 freshness 角色与 `seq_c` 的 burst 角色。
10. Item 相关强交叉只做少数白名单，并用 gate 或 evidence token 注入，避免低覆盖热点直接污染全局判断。
